# خطة النشر الكلاود — Gold Council

**الحالة: تصميم/مراجعة فقط — لا تنفيذ حتى يوصل ملف الإيميل + الباسورد + الـ APIs (أمر محمد 2026-11-13 22:33 EET: «متعملش حاجة لحد لما ابعتلك ملف»).**

## 1. الهدف

- المشروع شغال 24/7 ومش معتمد على جهاز نارمر ولا على الـ VM.
- أي حد يشوف الموقع من أي مكان في العالم على دومين `.dev`.
- قاعدة البيانات على Supabase (سحابة) بدل Postgres المحلي.
- الكود على GitHub كمصدر واحد للحقيقة.

## 2. الوضع الحالي (نارمر — حي من 2026-11-12 19:15 EET)

- البوت حي على نارمر: GoldCouncil-Poll كل دقيقتين، Cycle كل ساعة، Watchdog كل 15 دقيقة، N8N، Weekly (جمعة 18:00)، PollWeekly (أحد 12:00).
- Postgres محلي `gold_council`: 16 جدول، 9 إشارات (كلها مغلقة: 6 ربح TP1 / 3 خسارة SL، +0.67R)، 225 صوت وكيل.
- n8n 2.47.3 صحي (200) — ملفات الوركفلو التلاتة مستندات تصميم مش قابلة للاستيراد؛ الخط الفعلي بيمشي من المهام المجدولة (بايثون).
- الداشبورد على 127.0.0.1:8100 (localhost بس) + باسورد متثبت ومتأكد.
- WebApp ملفات ستاتيك + `data.json` محدث (9 مغلقة) — مفيش استضافة HTTPS.
- اللاندنج منشورة على رابط muse.ai.
- التوكن على نارمر (47 بايت، صلاحيات مقيدة).
- الـ VM أرشيف (poll/cycle متوقفين، watchdog شغال).

## 3. إيه اللي هيتغير وإيه اللي هيفضل

- **يفضل زي ما هو:** كود البوت، التوكن، منطق الإشارات، السجل، الداشبورد (نفس الكود)، نظام المراجعة، الـ 3/day cap.
- **يتغير:** مكان التشغيل (نارمر ← سحابة)، قاعدة البيانات (Postgres محلي ← Supabase)، استضافة الموقع (muse.ai ← `.dev` على Cloudflare)، إدارة الأسرار (ملفات محلية ← متغيرات بيئة + Secure Vault)، مصدر الكود (نارمر ← GitHub).

## 4. المكونات

### 4.1 GitHub — الكود

- ريبو جديد بالإيميل المخصص للمشروع (مالك الريبو = إيميل المشروع).
- المحتوى: `system/` (البوت + الداشبورد + WebApp)، `design/` (التصميم + schema)، `scripts/`، `docs/`.
- قبل أول push: تنظيف الأسرار — تأكد إن `.bot-token` و `.admin-password` و `.env` و `*.db` مش في الريبو (`.gitignore`)، وافحص الكود عن أي مفتاح مكتوب.
- GitLab مش ضروري دلوقتي (GitHub كافي).

### 4.2 Supabase — قاعدة البيانات

- مشروع جديد منفصل لمجلس الذهب (مش مشروع Eye of Justice `cbnxemyjzyzgrqaqrkhk` أبدًا).
- التطبيق: `schema.sql` (536 سطر، 16 جدول، RLS على الكل، 24 policy) — يتطبق من SQL Editor أو Management API بعد مراجعته.
- نقل البيانات من نارمر: 9 إشارات + 225 صوت + المشتركين/المدفوعات (0 حاليًا) + سجل التدقيق. سكربت الهجرة موجود (`migrate-sqlite-to-supabase.py`) لكنه مكتوب لـ Postgres عادي — يحتاج تعديل بسيط لـ Supabase (connection string الـ pooler + service_role).
- ملاحظة: RLS شغال على كل الجداول؛ البوت يتصل بـ `service_role` (يتخطى RLS) أو بـ owner. الـ `anon key` للقراءة العامة المحدودة فقط (لو احتجناها).
- الخطة المجانية كافية للمرحلة دي (500MB DB — إحنا مش بنستخدم Auth دلوقتي).

### 4.3 Cloudflare + الدومين `.dev`

- الدومين: لو لسه مش مشتريه، الشراء من Cloudflare Registrar (بسعر التكلفة ~$12/سنة) أو أي مسجل وتحويل الـ nameservers لـ Cloudflare.
- DNS:
  - `goldcouncil.dev` (أو الاسم اللي اختاره) ← Pages (اللاندنج + WebApp).
  - `admin.goldcouncil.dev` ← Tunnel أو الـ VPS (الداشبورد، محمي بالباسورد + يفضل Cloudflare Access كطبقة تانية).
- SSL: Cloudflare بيديه مجانًا (Full Strict مع شهادة على السيرفر).
- Pages: اللاندنج + WebApp ستاتيك من GitHub (deploy تلقائي مع كل push).

### 4.4 مكان تشغيل البوت 24/7 — البدائل

| | أ: نارمر + Tunnel | ب: VPS | ج: PaaS (Render/Railway/Fly) |
|---|---|---|---|
| التكلفة | $0 | ~$5/شهر | مجاني محدود / بيخلص |
| الاعتماد | جهاز محمد الشخصي لازم يفضل شغال 24/7 (ضد وضع on-demand) | مستقل تمامًا | مستقل |
| بعد إعادة التشغيل | خدمات Manual لازم تشغيل يدوي | systemd بيرجعها تلقائي | تلقائي |
| ملفات SQLite (journal/subs) | موجودة | موجودة (قرص دائم) | **مشكلة: نظام ملفات مؤقت — لازم نقل الحالة لـ Postgres (تعديل كبير)** |
| n8n | موجود | يتثبت كخدمة | محتاج استضافة منفصلة |
| الصيانة | هو بيدير جهازه | تحديثات + نسخ احتياطي علينا | قليلة |

**التوصية: (ب) VPS** — أرخص طريق مستقر لـ 24/7، والـ SQLite بيشتغل زي ما هو. (أ) بديل $0 لو مش عايز تكلفة شهرية بس البوت هيتوقف مع أي إعادة تشغيل أو قفل للجهاز. (ج) مش مناسب دلوقتي بسبب الـ SQLite.

- مواصفات VPS المقترحة: 1 vCPU / 1–2GB RAM / 25GB — كافية (البوت خفيف؛ الباكتست هو التقيل وبيتعمل على نارمر/VM مش على السيرفر).
- النظام: Ubuntu 24.04 + Python 3.12 + الكود + (اختياري) n8n كخدمة.
- ملاحظة: قرار محمد في 2026-10-30 لمشروع جديد منفصل كان Ubuntu Server + Supabase + Cloudflare — نفس الاتجاه ده.

### 4.5 الموقع — إيه اللي يتنشر

- اللاندنج: تتنقل من muse.ai لـ `.dev` (Pages).
- WebApp (تيليجرام): يتنشر ستاتيك على `.dev` — كده يبقى فيه HTTPS URL يتسجل في BotFather.
- الداشبورد: **مش** على الدومين العام المفتوح؛ على subdomain محمي بالباسورد (نفس باسورد نارمر أو باسورد جديد — يتثبت بملف ويتحذف).
- السجل العام: اللاندنج تعرض من `data.json` (بيتحدث مع كل إشارة مغلقة — لازم أتمتة التحديث بعد النشر: `build_data.py` + deploy).

### 4.6 Telegram

- التوكن نفسه (موجود على نارمر) — يتنقل للسيرفر السحابي بصلاحيات 600.
- Polling (`getUpdates`) يفضل زي ما هو — مش محتاج webhook ولا endpoint عام.
- الـ WebApp URL الجديد يتسجل في BotFather بعد النشر.

### 4.7 n8n

- مش على المسار الحرج: الوركفلو مستندات تصميم، والخط بيمشي من المهام المجدولة.
- على VPS: يتثبت كخدمة systemd (اختياري). على PaaS: يتأجل.

### 4.8 الأسرار — إدارة المفاتيح

- الملف اللي هيبعته محمد (إيميل + باسورد + APIs): يتفك محتواه، الأسرار تتخزن في Secure Vault (الباسوردات) ومتغيرات بيئة السيرفر (مفاتيح الـ API)، ونسخة الملف المرفوعة **تتحذف** بعد التثبيت.
- ممنوع: أي مفتاح في الشات، أو في Git، أو في ملف عادي.
- باسورد إيميل جوجل للمشروع: للتسجيل/الدخول على الخدمات وقت الإعداد بس — البوت مش محتاجه وقت التشغيل.
- «كوريدذ»: خدمة مش معروفة — لازم توضيح قبل استخدام أي مفتاح منها.

## 5. تسلسل التنفيذ (بعد وصول الملف — كل خطوة بمراجعة قبلها)

1. مراجعة الملف: إيه الخدمات والمفاتيح الموجودة، وإيه الناقص.
2. GitHub: إنشاء الريبو + تنظيف الأسرار + أول push.
3. Supabase: إنشاء المشروع (بالإيميل المخصص) + تطبيق `schema.sql` + نقل بيانات نارمر + تحقق (16 جدول / RLS / 24 policy / 9 إشارات / 225 صوت).
4. VPS (لو اتختار): إنشاء السيرفر + تثبيت Python + نسخ الكود + إعداد systemd للـ poll/cycle/watchdog + اختبار دورة كاملة (shadow أولًا — من غير ما نوقف نارمر).
5. Cloudflare: شراء/تأكيد الدومين `.dev` + DNS + Pages للاندنج/WebApp + Tunnel أو subdomain للداشبورد.
6. اختبار شامل: بوت يرد على `/admin`، دورة إشارة، WebApp يفتح من تيليجرام، الداشبورد يفتح بالباسورد، الموقع يفتح من أي مكان.
7. التبديل: إيقاف مهام نارمر (تعطيل مش حذف) + تشغيل السحابة حي + مراقبة أول 24 ساعة.
8. تحديث اللاندنج: الرابط الجديد `.dev` بدل muse.ai.

- Supabase: $0 (free tier).

## 7. القرارات المفتوحة (من محمد)

1. مكان التشغيل: VPS ولا نارمر+Tunnel ولا PaaS؟ (التوصية VPS.)
2. الدومين `.dev`: اشتراه ولا لسه؟ والاسم الكامل إيه؟
3. «كوريدذ»: إيه الخدمة دي؟
4. الداشبورد: subdomain محمي بالباسورد ولا Tunnel بس (مش ظاهر على الإنترنت)؟
5. الـ VPS: مين يدفع/يمتلك الحساب (إيميل المشروع)؟
6. هل نحتفظ بنارمر كـ fallback بعد التبديل ولا نوقفه نهائي؟

## 8. مخاطر وملاحظات صريحة

- النقل للسحابة مش بيخلق حافة تداول — الاستراتيجية لسه بلا حافة مثبتة (t-stat +0.75)؛ السحابة بتحسن الوصول والتشغيل بس.
- لو اختار نارمر+Tunnel: أي قفل للجهاز أو إعادة تشغيل = البوت واقف لحد ما يشغله يدويًا.
- Supabase free tier له حدود (500MB، وعدد اتصالات محدود) — كافي دلوقتي، ولو كبر المشروع نراجع.
- الداشبورد على الإنترنت = سطح هجوم جديد — الباسورد القوي + Cloudflare Access (مجاني لحد 50 مستخدم) مطلوبين.
- نسخ احتياطي: قبل التبديل، نسخة كاملة من نارمر (DB + ملفات) — وجدولة نسخ دوري على السحابة بعدها.
